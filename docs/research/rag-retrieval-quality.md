# RAG 检索质量研究

> 记录对 RAG 系统检索层的持续研究。每次实验附测试数据，结论对应具体代码位置。

---

## 研究一：近义词场景下的检索质量（2026-04-06）

### 实验背景

**场景**：桌面近场音响系统客服  
**测试脚本**：`scripts/test_synonym_retrieval.py`  
**检索组合**：GTE-Qwen2 向量 + jieba BM25 + RRF 融合（k=60）  
**知识库**：8 条 FAQ，覆盖无声/杂音/蓝牙/低音等故障类型

**核心问题**：同一故障用"音箱""音响""扬声器""喇叭"描述，检索结果是否一致？

### 实验结果

**Top-1 命中率（15 个测试查询）**

| 检索方式 | 命中 | 命中率 |
|---------|------|-------|
| 向量（GTE-Qwen2） | 7/15 | 47% |
| BM25（jieba） | 9/15 | 60% |
| 混合 RRF | 10/15 | 67% |

**典型失败案例**

| 查询 | 向量 Top1 | 期望 |
|------|-----------|------|
| 「音响不出声」 | 喇叭发出爆音 (0.58) | 音箱没有声音 (a1) |
| 「喇叭没响」 | 喇叭发出爆音 (0.48) | 音箱没有声音 (a1) |
| 「音箱嗡嗡响」 | 喇叭发出爆音 (0.53) | 音响有杂音 (a2) |

**向量的典型误判模式**：同属"故障诊断"语义场的文档，余弦相似度接近，导致错误排名。例如"爆音"和"没声音"在 GTE-Qwen2 的向量空间里比"音响不出声"和"音箱没有声音"更近——两者都是音频故障，但不是同一问题。

---

### 学术定位

#### 核心问题：Vocabulary Mismatch Problem（词汇错位）

1960 年代 Maron & Kuhns 建立概率 IR 框架时就发现：**用户表述问题的词汇，与文档作者表述答案的词汇，天然不对齐**。

三个子类型在本实验中均出现：

| 子类型 | 本实验例子 | 本质 |
|--------|-----------|------|
| **Synonymy**（同义词）| "音箱" vs "音响" | 不同词指同一实体 |
| **Paraphrase**（述语改写）| "没有声音" vs "不出声" vs "没响" | 同一事件的不同语言化 |
| **Conceptual Gap**（认知跳跃）| "喇叭没响" → 查"音箱无声故障" | 用户视角 vs 文档视角 |

**中文特有加剧因素**：
- 切词歧义：jieba 把"不出声"切为 [不出, 声] 或 [不, 出声]，BM25 匹配概率各不同
- 产品领域同义词密度极高：一个设备有 4-6 个民间称呼
- 口语 vs 书面体差距大："没响" vs "无声故障"

---

### 解法谱系

#### 第一代：Query Expansion（查询扩展，1970s-2000s）

**Pseudo Relevance Feedback (PRF)**（Rocchio, 1971）  
取 Top-K 结果，提取高频词追加回查询，再检索一次。  
缺陷："query drift"——首轮结果差时扩展词是噪音。

**Thesaurus / WordNet Expansion**  
用同义词词典把查询词替换/追加近义词。  
缺陷：领域词典覆盖不足，"音箱/音响/喇叭"在通用词典里未必同义。

---

#### 第二代：Dense Retrieval（稠密检索，2019-2021）

**DPR**（Karpukhin et al., 2020, Facebook）：BERT 双塔，query 和 document 映射到同一向量空间。GTE-Qwen2 属于此类。

**局限（实验直接验证）**：Dense Retrieval 捕获的是**上下文语义分布相似性**，不是**事实等价性**。"音响不出声"和"喇叭发出爆音"都在"故障诊断"语义场里，向量距离比正确答案更近——这是 **False Semantic Similarity** 问题。

---

#### 第三代：Sparse + Dense Hybrid（混合检索，2021-2022）

本系统当前方案（BM25 + Dense + RRF）属于此代。

**SPLADE**（Formal et al., 2021, CentraleSupelec）：代表性工作。用 MLM 在词汇空间生成稀疏向量，兼具 BM25 的精确匹配和 BERT 的语义泛化，做**隐式同义词扩展**。

BEIR benchmark 结果：

| 方法 | NDCG@10 |
|------|---------|
| BM25 | 43.0 |
| DPR | 35.2 |
| SPLADE | 49.3 |
| BM25 + Dense RRF | 52.1 |
| SPLADE + Dense RRF | **54.8** |

---

#### 第四代：LLM-based Query Augmentation（2022-2023）

**HyDE**（Gao et al., 2022, CMU）：LLM 先生成"假设性答案文档"，用文档向量检索而非查询向量。

```
查询「喇叭没响」
  → LLM 生成：「当扬声器出现无声故障时，首先检查电源连接...」
  → 对生成文档做向量化
  → 文档-文档相似度 >> 查询-文档相似度
```

核心洞察：**文档和文档的语义距离，远小于查询和文档的语义距离**。

**Query2Doc**（Wang et al., 2023, Microsoft）：few-shot 生成扩展文档，MS-MARCO 上提升 ~3 NDCG。

**RAG-Fusion**（Shi et al., 2023）：LLM 生成多个角度查询变体，分别检索后 RRF 融合。

---

#### 第五代：Late Interaction（2020-2024）

**ColBERT**（Khattab & Zaharia, 2020, Stanford）：保留 token 级向量，用 MaxSim 精细匹配。

```
query tokens: [喇叭][没][响]
doc tokens:   [音箱][没有][声音][怎么][办]
得分 = max_sim([喇叭], doc_tokens)   ← [喇叭]和[音箱]在token空间可对齐
     + max_sim([没], doc_tokens)
     + max_sim([响], doc_tokens)
```

ColBERT-v2（2022）效果接近 cross-encoder reranker，延迟仅其 1/10。

---

### 当前系统改进路径

| 方向 | 学术对应 | 预期提升 | 实现成本 |
|------|---------|---------|---------|
| **知识库同义词增强** | 数据增强 | +20%+ | 极低，最高 ROI |
| **QueryRewriter 明确指示扩展同义词** | Query Expansion | +15-20% | 低，修改 prompt |
| **HyDE 模式** | HyDE 2022 | +10-15% | 中，改 pipeline |
| **RAG-Fusion（多 query 变体）** | RAG-Fusion 2023 | +15% | 中 |
| 替换为 SPLADE | 第三代升级 | +8-12% | 高，需新模型 |
| ColBERT Late Interaction | 第五代 | +5-10% | 高，架构大改 |

**最高 ROI 立即可做**：FAQ 条目写入同义词覆盖：
```
Q: 音箱/音响/扬声器/喇叭 没有声音/不出声/没响 怎么办？
```
零额外计算成本，对 BM25 和向量检索都有效。
